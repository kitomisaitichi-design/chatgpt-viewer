# Offline Chat Viewer 1.1.11

Repairs saved images failing to appear in large, actively updated exporter archives. The image catalog could exceed the reader timeout, and each image request rebuilt the complete attachment catalog twice. Metadata construction now avoids filesystem resolution for every missing file, reference deduplication uses stable tuple keys, and image delivery reuses bounded thread snapshots while validating each requested file immediately before streaming.

Native attachment filenames no longer count the same alias twice. Catalog requests have a bounded 60-second cold-read allowance; errors are visible beside Retry, retry requests coalesce, and failed work from a previous chat is ignored. Original exports, prefixed writing cards, LaTeX, organization, preferences and backup slots are preserved.

Validation: 229 backend tests (one symlink-creation check skipped locally where Windows denies symlink creation); all web JavaScript syntax and four renderer/catalog/gallery checks. Real-archive API reproduction confirmed a 19-second catalog and 39-second first-byte delay before repair; a fresh repaired catalog took 5.3 seconds and direct image lookup was below the 1 ms timer resolution. These are local observations, not a universal performance guarantee. Actual affected-message thumbnails and IMG_0058.jpeg (1152×1536) were verified in Edge, including wheel zoom, fitted swipe and next-image navigation. Final reload/double-open/package checks are recorded in local release results.

Upgrade: close the viewer, replace application files, keep .viewer-data, Backups and the shared OfflineChatViewer profile. No conversation reindex is required. The portable excludes personal archives, account-specific ground truth and test fixtures. Cloud delivery and unattended scheduling were not re-tested for this image-only repair.
